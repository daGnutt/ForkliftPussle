# Code guide (for AI agents)

Read this first for a map of the code. Vanilla JS ES modules + Canvas 2D, no build, no dependencies. Source lives in `js/`, tests in `test/game.test.js` (`npm test`).

## Units and coordinates
- Simulation units are tiles; one box is 1×1. The renderer scales the canvas.
- x right, y down; angle `a` in radians, 0 = facing +x.
- Forklift local frame: x forward, y right, origin at the **front** axle; rear wheels steer. `toWorld`/`toLocal` convert.

## Game state `g` (from `newGame`)
- `walls`: border + interior wall rects with a `poly` (collision). `pillars`: the raw interior wall rects (for drawing).
- `zones`: `{x, y, color, count}` targets. `areas`: `{color, x, y, w, h}` tinted regions; all zones of a colour sit in one area.
- `stacks`: floor stacks `{x, y, layers, a}`; `layers` are colour indices into `COLORS` (bottom → top); `rots` is a parallel array with each box's own world angle (remembered through lift/drop/merge); `a` is the bottom box's angle, used for collision. `offs` is a parallel array of each box's world offset `{x, y}` from the stack position (`offs[0]` = 0), so towers can be crooked; `pen` is a parallel array of `{crash, sq, deco}` per box (point deductions and decal kind).
- `fl`: forklift `{x, y, a, speed, steer}`.
- `carried`: array of layers being carried, or `null`; `carriedRots`: each carried box's angle relative to the forklift (so they turn with it, and keep their world angle when dropped); `carriedOffs`: each carried box's offset from the carried bottom box in the forklift's frame (`carriedWorldOffs(g)` rotates it to world); `carriedRel` = `carriedRots[0]`, used for collision. `carriedPen`: the carried boxes' `pen` entries.
- `H`: logical fork level (integer 0–5); `hf`: smoothed value used only for drawing.
- `parking`: `{x, y, a}` centre/heading of the parking spot (the forklift's spawn pose; random per level, axis-aligned heading, tail resting against a charger: a half-truck-width stub added to `walls`/`pillars` jutting 0.45 from a random outer wall, generated in `level.js` `tryGenerate`; also returned as `charger`/`g.charger`, flagged `charger: true` in `g.walls`, drawn red with high-voltage decals: `drawCharger` in `render.js`, a 0.9-high (1.5 boxes) prism in `pov.js` with `drawChargerDecal`). When the spot turns green it also shows an arrow for the required heading (`render.js`, `pov.js`).
- `hits`: damage popups `{x, y, z, pts, t}` (z in box heights, `t` = `g.clock` at creation), created by `hurt()` in `game.js` whenever crash points are actually added and dropped after `HIT_LIFE` (1.2 s); `hitCount` increases per popup (`main.js` plays `playBreak` when it rises). Drawn as floating red `−pts` text in the overview (`drawOverview`) and the big cabin view (`drawHits` in `pov.js`).
- `status`: `'play'` or `'won'`; `time`: level timer in seconds, starts when the truck first moves (`started`), stops once `status` is `'won'` and restarts at 0 with the next `newGame`; `clock`: always-running animation clock (hit popups, blink).

## Rules (see `game.js`)
- Fork level `H` = box heights above the floor. A stack of n boxes spans heights 0..n. `forkUp` lifts the box at height `H` and everything above it; level 0 lifts the whole stack.
- Raised forks are top-heavy and slow the forklift down: top speed and acceleration scale by `heightSpeedFactor(g.H)` (`forklift.js`, linear from 1 at `H=0` to `MIN_SPEED_FACTOR` at `H=MAX_H`); exceeding the new cap after raising the forks bleeds off like rolling resistance rather than snapping instantly. Braking is unaffected by height.
- **Hard mode** (`g.hard`, `newGame(n, seed, hard)`; splash checkbox `#hardOpt`, persisted in `localStorage` `forklift-hard`, toggling restarts the current level) enables the pallet rules below (pallet runner collisions, tine torque, gliding, split damage). Off by default: forks lift from any angle and tines never collide.
- There is no entry-angle rule: forks only get into a pallet because the tines physically fit its slots (below); `forkUp` lifts the stack whose box at the fork level is in the fork zone (`forkedStack`). A pallet on the tines glides with them (`glideWithForks`): while the forklift turns it stays fixed sideways relative to the forks and turns with them, but keeps its world position along the fork axis, so driving in/out slides the forks through it. The whole stack moves, but only boxes from the fork level upward (`rots[i]`, i ≥ `H`) turn; `a` (bottom box) only changes at level 0. Not lifted.
- A tine push with the forks above the bottom box (`H > 0`) only gives crash points to the boxes below the forks (`pen.slice(0, H)`), unless speed ≥ `FORK_PUSH_FAST` (2), when the whole stack is damaged.
- Tines collide with the pallet's *runners* (`palletRunners`: a centre runner and two outer boards along the nearest square axis to the forklift heading, leaving a slot per tine) of any stack taller than `H`; square-on they slide into the slots. A tine pushing off-centre turns the pallet by the lever arm of the push (`spinPallet`, boxes from the fork level upward, clamped per contact).
- Otherwise tines never collide with boxes. Only the forklift body and the carried stack (when `stack.layers.length > g.H`) do.
- Empty `forkDown` with a box under the forks (`stack.layers.length >= H`, `H > 0`) is refused: returns `'blocked'`, adds 10 crash points (`FORK_BLOCK_POINTS`) to that box; `main.js` then plays `playBlocked`.
- `forkDown` releases the carried stack automatically at its resting height (top of the stack below, or the floor), merging into it at the position it was released (keeping its offset, so towers can be crooked). `settle()` (also run after a box is pushed) makes any box with less than `MIN_SUPPORT` (50%, `overlapArea`) of its area on the box below fall, with everything above it, 1.45 tiles beside the stack as a new stack with maximum crash damage. Carried boxes collide with and push the boxes of a stack at level ≥ `H` individually (`shiftBoxes`; pushing box 0 moves the whole stack), tines push the box at level `H` and above; the body and stack-vs-wall/stack collisions still use the bottom box only. Max 5 layers (`MAX_LAYERS`). Ceiling: `forkUp` with a carried stack refuses ('blocked', `main.js` plays `playBlocked`, plus `playBreak` via `hitCount`) when `H + carried.length >= CEILING_LEVELS` (6) and gives every carried box `CEILING_POINTS` (10) crash points.
- A zone is done only when a stack of exactly `zone.count` boxes, all of `zone.color`, is within 0.5 of it. Winning (`isFinished`) = all zones done (`isSolved`) AND `score ≥ 50%` of `maxScore` AND forklift parked (`isParked`: within 0.6 of the spot, heading within 0.35 rad, speed < 0.5).
- Nudging: when the forklift body touches a stack while driving forward slowly (0.05 ≤ speed < `CRASH_MIN_SPEED`), `resolve()` collects it in `g.aligning` and `update()` turns every box (`rots`, `a`) towards the nearest square angle to the forklift heading (`ALIGN_RATE`); a multi-box stack's bottom box takes `ALIGN_DAMAGE` crash points per radian turned. Such slow contact is not counted as a crash.
- `resolve()` runs iterative SAT: forklift shapes vs walls; forklift shapes vs stacks (mass-weighted pushing); stacks vs walls; stacks vs stacks.

## Scoring (`game.js`)
- Each box is worth 100 points, but only boxes in a stack that completes a zone count towards `score(g)`; score = sum of (100 − crash − square) over those boxes, so it starts at 0 on every `newGame` and rises as zones are filled; `maxScore` is 100 × all boxes.
- Crash (up to 50 per box): forklift body or carried boxes hitting a floor stack, stack-vs-stack contact, or carried boxes hitting a wall, at forklift speed ≥ 0.8 (1–5 points, 0.4 s cooldown per stack/carried group).
- Squareness (up to 50 per box): on release in `forkDown`, deduction scales with the box's deviation from the nearest multiple of 90° (free within 5°, then floored to steps of 5 points); `sq` of floor stacks is recomputed from the current `rots` whenever `score`/`lostBreakdown` run (`refreshSquare`), so nudging a stack straight or crooked, or re-placing a box, changes its squareness points immediately (crash losses are permanent). `lostBreakdown(g)` returns `{crash, square}` totals (`square` only counts stacks that fill a zone, so nudging a stack into or out of a drop point changes it); the HUD shows both under the score.

## Level generation (`level.js`)
- Deterministic per (level number, seed) via `mulberry32`; `generateLevel(n, seed = 0)`, seed 0 = the default layouts. `parseSeed(text)` maps splash input to an int (integers as-is, other text hashed). `newGame(n, seed)` stores `g.seed`; retries up to 300 attempts and falls back to level 1 if placement keeps failing.
- Order: choose boxes and zone counts per colour → rooms (`buildRooms`: recursive splits into rooms/corridors by thickness-1 dividing walls, each with one 3.6-wide door, or two (40% chance when the wall is long enough, ≥1.5 of wall between them); later walls keep clear of earlier doors so everything stays connected; `levelParams.dividers`, 0 on level 1) → per-colour zone area (preferably flush against an outer wall, 0.5 gap) → stack placement avoiding areas, walls and the start.
- Guarantees valid placement and matching box/zone counts, **not** solvability. Difficulty scales in `levelParams` (map width caps at 44 tiles, height 0.7× that; up to 40 boxes and 10 dividers; larger maps rely on the follow camera).

## Rendering (`render.js`)
- Height is faked with a parallax offset (`PX`/`PY`). Draw order: floor/grid → areas → zones → low stacks → forklift body → tines → high stacks → carried stack → pillars → HUD.
- The forklift is drawn from extruded `block(ctx, f, x0, y0, x1, y1, z0, z1, col)` calls in its local frame (wheels, chassis, counterweight, mast, overhead guard) using the same parallax as boxes.
- `drawStack(ctx, layers, x, y, z0, rots)` draws boxes as extruded cubes (shaded side faces facing the floor-ward parallax direction, gradient lid with tape strip), each with its own angle from `rots`; the top box shows its colour and the boxes below appear as coloured numbers.

## Branding / splash
- `js/splash.js` (`startSplashAnimation(canvas, isActive)`) animates `#splashAnim` on the splash: a forklift driving a figure eight (Gerono lemniscate), drifting (extra body yaw) through the end turns with rear-wheel permanent skidmarks (pre-driven for a few laps at load) and smoke. Decorative only; stops when `isActive()` returns false.
- Game name: Forklift Frenzy. `favicon.svg` is the tab icon; `#splash` in `index.html` (styled in `style.css`) has a seed text box and a shuffle-icon button (fills a random integer) (persisted in `localStorage` `forklift-seed`; submitting with Enter/Start applies it and restarts at level 1). The splash also shows a credits line (designed by Gnutt, coded by Copilot for GitHub). It is dismissed only by Enter or the Start button (handled in `main.js`, which pauses the simulation until then and swallows other keys).

The splash has a `.scoring` paragraph explaining the score; the 'Level complete!' overlay in `render.js` shows the breakdown (box points − crash − squareness, time penalty, final score via `finalScore`).

## PWA
- `manifest.webmanifest` (fullscreen/standalone, orientation `any` so it rotates, icons in `icons/` rendered from `favicon.svg`) and `sw.js` (precaches core files in `CORE`, network-first (`cache: 'no-cache'`, bypassing the HTTP cache) with cache fallback (offline or after a 3 s timeout) for everything else; the page re-checks for a new worker on `visibilitychange`/`pageshow` and reloads once on `controllerchange`, so MIDI is cached on first play). `index.html` registers the worker. Add new JS modules to `CORE` in `sw.js` and bump `CACHE` when shipping changes.

## Tests
- `test/game.test.js` is a sequence of independent blocks (plain `node:assert`). Helpers: `run` (simulate seconds of input), `driveUntil`, `flatWorld` (clears zones and pillars). Any game-logic change needs a scenario here.

## Workflow conventions
- Each fix or feature goes on its own local branch (not pushed); never merge into `main` unless the user explicitly asks; delete the branch only after such a merge.
- Update `README.md` when controls or rules change, and this guide when structure changes.
- `docs/presentation.html` (+ `docs/shots/`) is the development-timeline slide deck; `docs/PRESENTATION_GUIDE.md` explains how to regenerate/update it. Update it on merges that add notable features.
