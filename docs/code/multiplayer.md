# Multiplayer (party)

- Inspector scene snapshots are removed from the 30 Hz messages and sent once per picture to each guest over the reliable channel in 12,000-character `photoScene` chunks. Guests reassemble them and attach them to matching inspector reports by photo ID; level changes clear the transfer cache and resend the current scenes.
- **Lifting trucks**: truck fields `lifting` (id of the truck on this truck's tines, -1 none), `liftedBy` (id of the carrier, -1 none), `liftRel` (±π/2, heading relative to the carrier) and `perchZ` (> 0: sitting on stacks that many levels up, immobile). `forkUp` (`truckOnMyTines`: tines at floor level `H === perchZ`, carry point under the middle of the truck's side, perpendicular headings) lifts; `liftedPose` places the body centre at the carry point and `syncLifted` copies it into the lifted truck's `fl` every step (a lifted truck's `stepTruck` only syncs). The carrier's `forkShapes` gain shapes for the lifted body and its carried stack, so walls/stacks stop them. `forkDown` releases at `supportLevels` (stack tops under the truck): 0 = floor, else `perchZ`; perched trucks re-check support each step and fall when it vanishes. `liftBlocked`: ceiling like carried stacks (extent = victim `H` + carried length, else 1) and damages the victim's carried stack. A truck perched on a stack goes with it when the stack is taken (`perchedOn` in `forkUp`): it gets `liftedBy` = carrier, `rideLv` (boxes it sits above the forks) and `rideOff` (its pose in the carrier's frame, used by `riderPose`), the carrier's `lifting` points at it; setting the stack down (or the stack leaving the forks, see `syncLifted`) perches it again via `releaseLifted`; ceiling check adds the rider's height. `liftedHf(g)` (levels incl. tine thickness, null = on the floor) shifts rendering (GL `liftDz` in `models.js`, 2D translate in `render.js`) and the cabin eye (`gl/camera.js`, `pov.js`); the software cabin view does not draw other trucks lifted. Fields are in `net/protocol.js` `TRUCK_FIELDS` and `net/predict.js`.

- `game.js` keeps per-truck state in `g.trucks[]` (`makeTruck`: `fl`, `H`, `hf`, `carried*`, `input`, `name`, `color`, `gone`, ghost flags). `g` itself is the *view* of the local truck (`g.self`); `truckView(g, i)` Proxies expose other trucks with the same field names. Never serialise views or hit `owner` fields. `addTruck(g, name, slot)`/`removeTruck`, `liveTrucks`, `otherTrucks`, `isGhost`/`ghostBetween` (trucks overlapping at spawn are ghosts to each other until separated), solid truck-vs-truck SAT in `resolve()`, and stack handoff (`transferCarried` in `forkUp`/`forkDown`: tines under another truck's carried stack at height <= theirs take it on reaching its height, tines inside it at level k split off the boxes from k up; lowering over another's empty tines gives the stack, over a truck carrying a stack merges onto it (max `MAX_LAYERS`); carried stacks of two trucks only collide when their height ranges overlap). `isFinished` = any live truck parked. `dropLift` is shared by the cabin renderers.
- `forklift.js`: `MAX_PLAYERS` (4), `TRUCK_COLORS` (yellow, red, blue, green; `body/roof/counter/dark`), `truckColor(i)`. The fork gauge backdrop uses `dark`; in local multiplayer (`view.shared`) `render.js` draws one `drawForkGauge` per live truck (via `truckView`), the extra ones stepping left of the first.
- `js/net/`: `relay.js` (hiScore party API: create/info/join/signal/end + SSE events), `peer.js` (RTCPeerConnection with reliable `ctl` and unordered `state` channels, serial signal handling, ICE buffering), `protocol.js` (`snapshot`, `createSnapshotter`, `applySnapshot`, `createInterpolator` ~100 ms delay, 30 Hz), `host.js` (authoritative: `hello` -> `addTruck` -> `welcome`, applies `in`/`fork`, broadcasts snapshots), `guest.js` (sends inputs, `interp` renders snapshots, measures its round trip `rtt` with `gping`/`gpong` on the reliable channel), `predict.js` (client-side prediction of the guest's own truck: `createPredictor` keeps a private `newGame` copy, steps only the guest's truck with the held keys each frame (others frozen, stacks from the latest snapshot; stacks the guest pushes keep their predicted position for 0.5 s), and on each snapshot compares the host's truck with the prediction from one `rtt` ago, blending 20% of the error away or snapping beyond 2 tiles; fork actions are predicted too (`predictor.fork` runs `forkUp`/`forkDown` on the private game; the predicted fork state and stacks are displayed until `rtt` + 0.3 s after the action, then any difference from the snapshot (fork level, carried stack, stack structure) is replaced by the host's, which stays the source of truth); `main.js` calls `predictor.step`/`apply` after `interp.apply` and `reset` on every level). All DOM-free and tested in Node with an in-memory relay and loopback links.
- `main.js` holds `mp` (`{role, code, host|guest, ...}`): guests never call `update`; hosts broadcast every frame; the menu does not pause in a party; savestates/import are disabled for guests/parties. Party UI: splash `#party` block, `#menuLeave` (End game leaves a party or closes it for all guests when used by the host), party badge `drawPartyBadge` in `render.js`.
- Menu page `party` (Esc menu → Multiplayer, `renderMpPage` in `main.js`): hosts a game from a running level, lists the party (host, including observer: ping per guest, Kick/Ban buttons) and leaves. During an online or joined local multiplayer session the Multiplayer button is the first navigation option after the main actions and is bold. A join link fills the code and asks the player to confirm their saved name; `multiplayer` is removed from the URL only on host welcome. The host pings guests every 2 s (`ping`/`pong` on the reliable channel; `players()` returns `{slot,name,ping}`); `host.kick(slot, ban)` sends `bye` and removes the truck; kicks block the lower-case name for 60 s and bans last for the party. Names are not secure identities (relay peer ids change per join). A guest that rejoins under a name held by a member that has been silent for `STALE` (3 s; guests message at least every second; e.g. after a page reload, before the old link times out) replaces that stale member and gets its slot back; `interp.reset(stacks)` seeds the interpolator with the welcome/level snapshot's stacks, so stacks are not stale until the next full refresh.
- Stacks under a spawning truck get `ghost: [truck ids]` (`markSpawnStacks` in `addTruck`/`newGame`): that truck skips them in `resolve()` and the GL scene draws them translucent for it; `updateGhosts` clears the flag once the body is off the stack. The endless start is top centre facing south.
- Prediction tracks changes to stack positions, angles and per-box offsets, and displays those changes until the host state takes over. Authoritative updates replace the predicted stack fields in place, preserving endless cargo references.
- Hard-mode `hello` and level messages exchange `hardPhysicsVersion`; incompatible peers are disconnected with a reload message, including when an easy-mode party changes to hard. Held fork movement remains predicted until the confirmation window expires, then the host can correct fractional tine height even within the same level.
- Endless mode in a party: `levelInfo()` carries `endless`, so guests build `newEndless(seed, hard)`; `snapshot` adds `endless: endlessSnapshot(g)` (bays/docks state, cargo as stack indices) and `applySnapshot` calls `restoreEndless` when it changed (`g.endlessSrc`); the predictor builds its sim with `newEndless` and shares the displayed game's `walls`/`pillars`. The host's `loadEndless` starts a fresh shared game (no saved-state resume in a party) and calls `partyGameChanged`.
- Pop in/out: `main.js watchPops` compares each other truck's `gone` flag per frame (first sight of a game is silent, and unused player slots are remembered as gone so a later first join pops); a change queues `{n, x, y, t}` in `g.pops` (kept 2 s, view-only, not in snapshots), plays `audio.playPop` (volume by distance) and `gl/particles.js watchPops` emits a big smoke cloud, dust ring, sparks, confetti and stars at the spot (GL views only). `g.popVis[slot] = {t, kind}` drives a view-only scale animation for `POP_DELAY` (0.8 s): incoming trucks appear tiny and scale up, while departing trucks wait half the delay for the smoke to build before shrinking to tiny and disappearing. Renderers draw `otherTrucksShown(g)` instead of `otherTrucks(g)` (the sim keeps using `otherTrucks`).
- Party scores: host calls `submitPartyScore` (`globalscores.js`) to board `<seed||0>:<level>:p<N>` with `players`, `partyCode`, `hostToken`.
- Observer rounds: `net/round.js` tracks names of guests who participated in a round and the guests connected at its end. A per-tab session ID avoids counting a reconnect twice; it is not an authenticated identity. On a win or endless game over the host starts a 10 s countdown, sends reliable round state to guests and submits one shared score with the full roster (endless board level 0), including guests who left. The first participant is the score's name; the observer host is not included. No score is submitted without participants. Guests can press Ready/OK; when every still-connected eligible guest is ready, including when none remain, the deadline is shortened to at most 3 s. Late joiners do not block it. The host advances automatically; manual advance/restart is disabled during the countdown. Rosters larger than the simultaneous player limit require the updated score service.
- Multiplayer votes: `net/vote.js` permits one 20 s anonymous majority vote at a time for easy/hard mode, a numbered level, endless mode, or kicking another player. Voting is enabled by default in online and local games; the host can disable or re-enable it from the Multiplayer menu, cancelling an active ballot when disabled. In online parties the host enforces this setting, sends it and aggregate yes/no totals to guests, and applies passed actions; ballots are keyed by connection only for tallying. A live vote is announced in a notice on every screen, including observers. Any joined player or the observer host may call a vote; eligible players (including a driving host, never an observer host) vote in the menu. In local multiplayer the keyboard player calls and votes through the shared menu and joined gamepads vote with A/B while the menu is open; only aggregate counts are displayed, though physical privacy depends on players sharing the screen. A kicked local pad may rejoin using A. A vote's electorate is fixed when called, disconnects are removed from it, and a kick target leaving cancels that vote.

**Wide boxes**: always gray (`WIDE_COLOR` = 5, the sixth `COLORS` entry; the generator and endless mode only use 0..4 otherwise), so any wide box fits any wide zone; a box whose `pen.wide` is true is 1×2 tiles (half extents 0.5 along the box's local x = fork axis, 1.0 along local y; `halfY(pen)`), only ever stacked with other wide boxes (a stack is all wide or none: `wideBox(pens)` looks at the first box; `wonkyStack` gives every layer the same exact angle): the `stackPoly`/carried/fork shapes, `reach(s)` rejection radii, `boxMass`, pallet runners (two pallets) and the three renderers (`render.js`, `gl/models.js`, `pov/scene.js`) all honour it. In hard mode `forkUp` requires both tines to overlap the pallet without hitting its runners; in easy mode it uses the fork-zone and `WIDE_ALIGN` checks. It can only be put down on a wide stack, and only wide boxes on it (`forkDown` rest height stays one above when `wideBox` of the stack and of the carried boxes differ; handovers refuse wide boxes; `settle` landings only join stacks of the same kind), and is worth `boxPoints` = 200. Layouts: `level.js` `markWide`/`tryWide` (own RNG, level ≥ 3, up to 4 zones) swaps normal zones (count ≤ 3) for wide zones (`zone.wide`, `hx`/`hy` world half extents via `zoneExt`, `a`, same `count`), taking that many boxes of the zone's colour out of the stacks; all wide zones share one gray area laid out on a grid, and the same number of wide boxes stand in 1–3-high wide stacks (`stack.wide`, `a` 0 or π/2) in 2×2 bays of their own. `stackFillsZone` needs `wide` to match and the box lined up with the zone (mod π). Not used in endless.

**Observer host**: the splash's Start observer mode button requests fullscreen immediately (before hosting) and starts as soon as the party is ready; this does not change the saved auto-fullscreen preference for normal games. `?observer` hosts and starts automatically (`?multiplayer` takes precedence); browsers may block fullscreen without a user gesture. The in-game party setup also has an observer checkbox. Observer hosts use the temporary name `Observer` without changing the saved player name. It removes the host truck, reserves all four truck slots for guests and forces the whole-map overview. The slot-0 local view remains as a gone placeholder until a guest joins; renderers skip it and `update(g, null, dt)` steps every live truck using its own network input, including slot 0. The top score bar remains visible in fullscreen. Observer driving controls, fork gauges, zoom and tutorials are hidden; the Menu button remains, with only Resume, Restart level, End game, level selection, hard mode, colour mode and player management. `observerLayout` fits the map without reserving join-card space. The tilted Polaroid-style join card floats over the overview, smoothly relocating among screen positions to minimise overlap in strict priority order: live forklifts, boxes (including carried boxes), drop zones, then visible bots. It stays at least 180 CSS px wide even on crowded maps, and disappears once four guests are live. Placement uses the actual GL projection (including height) or the 2D overview's parallax; rotated card bounds stay below the score bar and inside the viewport when it can fit. `view.observerCard` holds view-only position/timing, not game state. `js/qr.js` generates the QR matrix locally for `?multiplayer=<party code>`; URLs too long for its supported versions fall back to manual code entry. No package or build step is used.
