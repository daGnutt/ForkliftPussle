# Branding, PWA, tests, workflow

## Branding / splash
- `js/splash.js` (`startSplashAnimation(canvas, isActive)`) animates `#splashAnim` on the splash: a forklift driving a figure eight (Gerono lemniscate), drifting (extra body yaw) through the end turns with rear-wheel permanent skidmarks (pre-driven for a few laps at load) and smoke. Decorative only; stops when `isActive()` returns false.
- Both splash renderers use `js/visible-loop.js` to cancel animation frames and delayed callbacks while hidden; visible return resets animation timing, and the loop restarts only while the splash remains active.
- If the page loads hidden, the splash skips its pre-driven opening steps until it is visible; no hidden-time simulation or drawing is performed.
- Game name: Pallet Polka. `favicon.svg` is the tab icon; `#splash` in `index.html` (styled in `style.css`) has no seed field: the seed comes only from the URL parameter `?seed=` (read once at load into `seedText`/`seed`, max 32 chars; not persisted; meant for tournaments; the old `forklift-seed` key is unused; a guest takes the host's seed). The splash also shows a credits line (designed by Gnutt, coded by Copilot for GitHub). The URL parameter `?skip` calls `startGame()` at load (end of setup in `main.js`) so the splash never shows (on touch it then opens the main menu and turns auto full-screen on for that visit only, so leaving the menu, a user gesture, enters fullscreen). It is otherwise dismissed only by Enter or the Start button (handled in `main.js`, which pauses the simulation until then and swallows other keys).

The splash has two submit buttons: `#startBtn` (Start, keeps saved settings; Enter does the same) and `#endlessStart` (Start endless: starts the endless mode via `loadEndless`). It shows a short `.story` blurb; the scoring text lives on the menu's "Info & scoring" page (`data-page="info"`). The 'Level complete!' overlay in `render.js` shows the breakdown (box points − crash − squareness, time penalty, final score via `finalScore`).

## PWA
- `manifest.webmanifest` (fullscreen/standalone, orientation `any` so it rotates, icons in `icons/` rendered from `favicon.svg`) and `sw.js` (precaches core files in `CORE`, network-first (`cache: 'no-cache'`, bypassing the HTTP cache) with cache fallback (offline or after a 3 s timeout) for everything else; the page re-checks for a new worker on `visibilitychange`/`pageshow` and reloads once on `controllerchange`, so MIDI is cached on first play). `index.html` registers the worker only on the official host (`!isTesting()`); elsewhere it unregisters workers and deletes caches. Add new JS modules to `CORE` in `sw.js` and bump `CACHE` when shipping changes. Save layout version is 4 for the updated barrel placements and zones.

## Battery Saver
- Graphics menu has separate options saved as `forklift-battery-saver-resolution`, `forklift-battery-saver-frame-rate` and `forklift-battery-saver-effects`. On coarse-pointer/touch devices, lower resolution and the 30 fps limit default on, while reduced effects default off; all three default off on desktop. The frame-rate option limits game and splash drawing and freezes the splash animation after 20 s; lower resolution caps the drawing canvas at DPR 1 and ~0.9M pixels; fewer effects suppresses decorative effects. The former `forklift-battery-saver` setting remains a fallback for users with an existing preference. The obsolete `forklift-battery-saver-autosave` preference is ignored: state saves happen only when opening the pause menu or starting/loading a level (including imports), with no periodic or page-exit saves. The main loop stops while a solo game is paused; multiplayer continues to run.

## Tests
- Tests are split by category, one file each: `level` (generator, bays, spawn), `bot` (cleaning bot), `physics` (steering, collisions, speed, gears, impacts), `fork` (lifting, carrying, lowering), `stacks` (pallets, pushing, toppling, box types), `score` (scoring, high scores, popups), `render` (drawing, GL scene, cameras, lights), `power` (battery-saver settings and render cadence), `audio` (Web Audio lifecycle), `save` (save/restore), `demo` (splash demo), `net` (multiplayer, networking), `endless`, `input` (gamepad polling). `npm test` runs all; `node test/run.js <category> ...` (e.g. `node test/run.js fork score`) runs only those. Each file is a sequence of independent blocks (plain `node:assert`). Shared helpers live in `test/common.js`: `run` (simulate seconds of input), `driveUntil`, `flatWorld` (clears zones and pillars), `faceStack`, `pts`, `NONE`. Any game-logic change needs a scenario in the matching category file. Run the relevant categories per commit, all of them before merging to `testing`, and again before merging to `main`. `npm test` preloads `test/trace.js` (+ `trace-hooks.js`), which prints `▶ [line N] title` before each top-level `// Title` comment group (and `· ` for blank-line-separated `  // sub-step` comments) and `done in X ms` after it, flagging `SLOW` at `SLOW_MS` (default 1000); `TRACE=0` silences it. Start a new test section with a `// Title` comment to get it traced.
- The `power` tests also cover `visible-loop.js` callback cancellation and restart behavior.

## Workflow conventions
- `docs/VOCABULARY.md` lists the shared names for game objects, views and UI; use those terms and keep it updated when adding/renaming things.
- Each fix or feature goes on its own local branch (not pushed); never merge into `main` unless the user explicitly asks; delete the branch only after such a merge.
- Update `README.md` when controls or rules change (its "URL parameters" table lists `?gl`, `?debug`, `?skip`, `?level`, `?local`, `?testing`; keep it updated when adding one), and this guide when structure changes.
- `docs/presentation.html` (+ `docs/shots/`) is the development-timeline slide deck; `docs/PRESENTATION_GUIDE.md` explains how to regenerate/update it. Update it on merges that add notable features.
- `docs/devlog.html` (+ `docs/devlog/*.webp`) is the detailed scrolling devlog (one entry per milestone, with screenshot or animation); see the *Devlog* section of `docs/PRESENTATION_GUIDE.md`.

**Impact physics** (`game.js`): `resolve` records `g.impacts` (`{x, y, nx, ny, w}`: contact point, push-out normal, share of the push the truck took) for body/carried-stack hits on walls and for fast (≥ `CRASH_MIN_SPEED`) body hits on stacks. `impactKick` turns the closing speed and the lever arm about the centre (`CENTRE_X`) into `fl.spin` (yaw rate) and `fl.sx/sy` (sideways skid velocity); `skidStep` applies and decays them before the next `drive`. Gentle/aligning contact and standing contact add nothing.

**Stack nudging** (`nudgeStack` in `game.js`): a fast (≥ `CRASH_MIN_SPEED`) body or stack-on-stack hit shifts the upper boxes' `offs` in the push direction, growing with the square of their height above the hit box, then `settle()` topples boxes left without `MIN_SUPPORT`. Rate-limited per stack by `CRASH_COOLDOWN`.

**Landing on another stack**: boxes that `settle()` drops off a stack land on the top box of another stack if that box is within 0.55 tiles on both axes of the landing spot and the result has ≤ `MAX_LAYERS` boxes (then `settle` runs on that stack too); otherwise they form a new stack.

**Fall animation** (`fallView`, `FALL_TIME` in `game.js`): `settle()` still moves fallen boxes to their landing spot at once, but tags the stack with `s.fall = {t0, dx, dy, dr, z, from}`. Renderers (2D `render.js`, `gl/scene.js`, `pov/scene.js`) draw `fallView(g, st)` instead of the stack: for 0.5 s the boxes from `from` upward slide in from where they toppled, tumble (`dr`) and drop (`fallZ`, only when they land as their own stack; `stackZ(st)` reads this drawing-only height). `update()` deletes `s.fall` when done. Logic never reads it.

**Fall spot** (`fallSpot` in `game.js`): boxes dropped by `settle()` land 1.45 tiles from the stack, but the spot is cut short at the first wall (`g.walls`, e.g. trailer sides) and other directions are tried if it ends up closer than 1.0, so boxes never end up inside or beyond a wall (unreachable).
